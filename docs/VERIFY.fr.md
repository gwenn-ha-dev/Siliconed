# Vérifier Siliconed

Siliconed affirme que chaque étage de chaque modèle qu'il livre calcule ce que calcule l'implémentation de référence. **Cette page montre comment le vérifier soi-même**, sur son Mac, sans nous croire sur parole.

La référence est celle de l'éditeur : [diffusers](https://github.com/huggingface/diffusers) et [transformers](https://github.com/huggingface/transformers), sur le CPU, avec les poids publiés. Des scripts Python de ce dépôt l'exécutent et figent ses réponses en *goldens* : en float32, en bfloat16 (le format des poids publiés, que la Standard lit), et en float64 là où un témoin exact tranche. `siliconed check` fait tourner le moteur sur les mêmes entrées et le juge contre elles, étage par étage : encodeur de texte, débruiteur, échantillonneur, décodeur, puis le rendu entier.

Ce qui n'est **pas** affirmé : les mêmes bits que la référence, ni qu'un autre Mac, ni que le même Mac après une mise à jour de macOS. Le moteur confie ses calculs à Core AI ([ENGINE](ENGINE.fr.md#core-ai)), dont les bits peuvent changer avec le système : deux rendus d'une même graine n'ont pas à être identiques au bit. Le moteur est jugé sur sa distance à la valeur exacte (la [règle](#la-règle) plus bas), pas sur ses bits. Ce qui reste exact, et jugé comme tel : les identifiants du tokenizer, le bruit d'une graine, le planning des σ.

Tout n'est pas vert, et cette page le dit : quelques mesures sortent rouges de quelques pour cent, par un comportement connu du bfloat16 ([plus bas](#ce-qui-sort-rouge-et-pourquoi)).

## Mise en place

Il faut un Mac Apple silicon sous macOS 27, l'app (0.31), Python 3.12, et ce dépôt à la version de l'app (Siliconed → À propos de Siliconed l'affiche). `siliconed` est livré dans l'app : c'est le moteur même avec lequel l'app rend, et il tourne sans Xcode.

```sh
alias siliconed=/Applications/Siliconed.app/Contents/Helpers/siliconed
git clone --branch v0.31 https://github.com/gwenn-ha-dev/Siliconed && cd Siliconed/App
python3.12 -m venv oracle-env && oracle-env/bin/pip install -r tools/oracle/requirements.txt
```

Toutes les commandes de cette page se lancent depuis `App/` : l'oracle est dans `App/tools/oracle/`.

La première exécution d'un script d'oracle télécharge les poids de référence depuis le Hugging Face Hub, à des révisions épinglées ; `HF_HOME` ou `HF_HUB_CACHE` décide où ils vont. La référence de Krea 2, `krea/Krea-2-Turbo`, est à accès restreint : acceptez sa licence sur le Hub, puis `oracle-env/bin/hf auth login`, avant `krea2.py` ; faites de même pour tout autre dépôt qui le demande. Le code int8 de ComfyUI dont l'oracle des versions Compact a besoin est récupéré une fois, à un commit épinglé, et son sha256 est vérifié.

`siliconed check` lit les poids de la bibliothèque de l'app, jamais ceux que télécharge l'oracle : un modèle s'installe d'abord, dans l'app ou par `siliconed install <modèle>` (`--variant compact` pour la Compact ; `siliconed models` dit ce qui est installé). L'app lit les fichiers publiés tels quels : bf16 pour la Standard, int8 pour la Compact.

Pour vérifier plutôt votre propre compilation : `swift build -c release --product siliconed` depuis `App/` ([ENGINE](ENGINE.fr.md#construire-depuis-les-sources)), puis `.build/release/siliconed` à la place de l'alias.

Chaque étape affiche le fichier de poids qu'elle lit (une ligne `map` : chemin, taille, types des tenseurs), ses mesures (pour un tenseur : l'écart à la référence float32, sa médiane, le pire canal, l'écart au témoin float64, la barre), une ligne `memory` (l'étage du moteur le plus près de son P, ou le plus au-delà : l'empreinte à son plus haut contre ce que son plan avait compté avant d'allouer) et une ligne `swap` (les pages échangées pendant ce temps, qui doivent être zéro), puis une ligne de verdict : `✓`, `✗` (avec les mesures en échec), ou `—` (sautée, avec la raison). Le code de sortie dit la même chose : 0 réussi, 1 échoué, 2 sauté, 64 erreur d'usage. Les goldens vont dans `./goldens`, pour les scripts comme pour les contrôles, sauf si `--goldens DIR` ou `SILICONED_GOLDENS` en dit autrement.

`siliconed check` juge sur le GPU seul, l'arithmétique propre du modèle, sauf si `--neural-engine on` laisse le moteur confier au Neural Engine sa propre part, comme le fait l'interrupteur Neural Engine de l'app ; `--neural-engine ROWS` (un nombre, qui l'allume) impose au Neural Engine les lignes données au lieu de la part du moteur, et `--neural-engine off` est le défaut. Un contrôle dont les étages du moteur ont donné une part au Neural Engine affiche une ligne de plus, dite et non jugée : `neural engine · <étage du moteur> N %, …`.

## 1 · Un modèle entier : Anima

Anima est le modèle le plus léger à vérifier de bout en bout. L'installer d'abord (Standard), dans l'app ou par `siliconed install anima`. Puis, à 512² :

```sh
oracle-env/bin/python tools/oracle/anima.py all --size 512              # la référence en float32, ses témoins float64
oracle-env/bin/python tools/oracle/anima.py text-bf16                   # la même référence en bfloat16, étage par étage
oracle-env/bin/python tools/oracle/anima.py block-bf16 --size 512
oracle-env/bin/python tools/oracle/anima.py bf16 --size 512
oracle-env/bin/python tools/oracle/anima.py trajectory-bf16 --size 512
oracle-env/bin/python tools/oracle/anima.py render-bf16 --size 512
oracle-env/bin/python tools/oracle/anima.py img2img-bf16 --size 512
siliconed check anima --size 512                                        # chaque étape à 512²
```

`all` écrit la référence en float32 et les témoins float64. Les références en bfloat16, contre lesquelles la Standard est jugée, s'écrivent étage par étage (celle du décodeur exceptée, que `all` écrit). Une étape dont une référence manque n'est pas jugée à moitié : elle est sautée, et sa ligne nomme le fichier absent et la commande qui l'écrit.

Une étape peut sortir rouge d'une mesure, et `siliconed check anima` finit alors sur le code 1 : un tel rouge est [dit plus bas](#ce-qui-sort-rouge-et-pourquoi), ce n'est pas une faute.

Vos chiffres différeront : la référence elle-même arrondit autrement sur un autre processeur, et les bits de Core AI peuvent changer avec le système. Un verdict net ne bouge pas ; une mesure à quelques pour cent de sa barre peut changer de côté. Une étape se lance aussi seule, `siliconed check anima dit --size 1024` ; `siliconed check list` les nomme toutes, avec leurs tailles. Sans `--size`, `siliconed check anima` passe chaque étape à chacune de ses tailles, et saute celles dont les goldens ne sont pas écrits.

| Anima | `anima.py` | `text-bf16`, `block-bf16`, `bf16`, `trajectory-bf16`, `render-bf16`, `img2img-bf16` |

Les scripts de Z-Image, d'Anima et de Krea 2 prennent `--size` (512, 1024, un rectangle comme 768x512), `all` compris ; les références de Qwen-Image-2.1 sont à 512², celles de MOSS-Image aussi, son DiT excepté (`--size 1024`). La ligne de chaque étape dans `siliconed check list` donne les scripts qu'elle lit, avec leurs arguments. Le téléchargement des poids de référence vient en plus des poids de l'app. L'oracle fait passer le débruiteur et l'encodeur bloc par bloc en float32 plutôt que de les charger entiers. Une référence en bfloat16 d'une trajectoire est longue : sur un M5 Pro, une demi-heure pour celle de Qwen-Image-2.1, 35 à 60 minutes pour chacune des références bf16 de son édition. Les autres durées et les pics de mémoire des scripts ne sont pas encore relevés pour cette version.

### Ce qui sort rouge, et pourquoi

**Un rouge n'est pas toujours une faute du moteur, et aucune barre n'est déplacée pour en faire passer un.** Ces modèles sont publiés en bfloat16 et y ont un comportement limite : deux calculs fidèles en bf16 s'écartent l'un de l'autre autant que chacun s'écarte de la référence float32. Or la barre d'une mesure est l'écart d'*un* calcul bf16 de la référence, plus 25 % : un autre calcul bf16, tout aussi fidèle, tombe d'un côté ou de l'autre. Un tel rouge est le pire canal d'un pas ou d'une frontière, un peu au-dessus de sa barre.

Pourquoi le rendu d'Anima et de Qwen-Image-2.1 a une autre barre que 25 dB : le rendu de diffusers en bf16 est lui-même loin de son image float32 (23,08 dB pour Qwen-Image-2.1). Ces deux rendus se jugent donc à côté de lui : leur PSNR contre l'image float32 ne doit pas être de plus de 3 dB sous le sien.

Nous n'avons pas de référence bf16 à 1024² pour la trajectoire de Z-Image ni pour celle de Krea 2.

**Ce qui serait une faute**, et que nous ne laisserions pas passer : une erreur d'ensemble nettement au-dessus de celle de la référence bf16, un étage exact rouge (tokenizer, bruit, σ), une image fausse. Si vous voyez cela, une issue avec la sortie de `siliconed check` nous aide à trouver la couche qui porte l'écart.

## Vos goldens sont-ils les nôtres ?

Nous ne publions pas les goldens (plusieurs gigaoctets, et des poids dont les licences l'interdisent). Nous publions leurs empreintes : forme, type et statistiques de chaque tenseur.

```sh
oracle-env/bin/python tools/oracle/fingerprints.py compare
```

Les entiers (identifiants de tokens, masques) doivent concorder exactement. Les flottants se comparent avec une tolérance (1e-4 sur les normes, 1e-3 pour les trajectoires, qui enchaînent huit évaluations), pas au bit près : PyTorch sur le CPU ne promet pas les mêmes bits float32 d'une machine à l'autre, et deux exécutions honnêtes de la référence diffèrent d'un arrondi. Cet arrondi est très en dessous de ce que jugent les contrôles. Un golden que vous n'avez pas écrit est dit, pas compté comme un échec.

## La règle

Le chiffre d'une étape est l'**écart relatif par canal** : pour chaque canal (le dernier axe d'un tenseur, ou chaque plan d'un latent), la norme L2 de la différence sur la norme L2 de la référence. On donne le pire canal, jamais une moyenne : une faute confinée à un canal disparaîtrait dans un chiffre global. La même règle juge chaque frontière de chaque modèle :

    sans témoin :   écart(moteur, float32)  ≤ max(5e-4, 1,25 · écart(bf16, float32))
    avec témoin :   écart(moteur, témoin)   ≤ max(plancher, 1,25 · écart(référence, témoin))

`float32` est la référence en float32 sur le CPU ; `bf16`, la même référence exécutée en bfloat16 ; le *témoin*, le même calcul en float64. Là où le témoin existe, il tranche, et la `référence` de la seconde ligne est la plus éloignée de lui des deux, float32 ou bf16 : le moteur, qui calcule en bf16, peut être aussi loin de la valeur exacte que la référence en bf16, plus 25 %. Le plancher est 5e-4 par canal ; par plan d'un latent ou d'une image, au témoin, il n'y en a pas.

**La Standard se juge donc contre la référence en bf16.** La Compact se juge au DiT, la référence en int8 de son éditeur à la place de la référence bf16 ([plus bas](#au-delà-de-all)).

La ligne de chaque étape dans `check list` donne sa règle. Une identité (tokens, bruit d'une graine, plannings) se juge au bit près. Un rectangle se contrôle aussi contre sa transposée, qui doit échouer, pour qu'une hauteur et une largeur inversées ne passent pas.

Chaque décodeur se juge par plan de l'image au témoin float64 du décodeur de la référence (`vae-witness`) : pas plus loin de lui que diffusers décodant en bf16 (`vae-bf16`), plus 25 %. Celui de MOSS-Image décode en float32, comme sa référence, et se juge contre elle.

Le rendu entier (`render`) se juge sur l'image, par son PSNR contre l'image float32 de la référence : au-dessus de 25 dB pour Z-Image, Krea 2 et MOSS-Image, une barre écrite avant la mesure ; pour Anima et Qwen-Image-2.1, pas plus de 3 dB sous le PSNR du rendu de diffusers en bf16 contre la même image.

## Au-delà de `all`

`all` écrit ce que lit le gros des étapes. Le reste demande une étape de script de plus, ou un fichier que vous fournissez ; `siliconed check <modèle>` saute ce qui manque, et chaque contrôle se lance aussi seul.

**Les références en bfloat16.** La Standard est jugée contre elles ; `all` n'écrit que celle du décodeur. Leurs commandes sont dans la [table des modèles](#2--tous-les-modèles).

**Les prompts longs.** Z-Image admet jusqu'à 1 024 tokens de prompt ; le pipeline de référence coupe à 512 par défaut. `tokenizer --long` vérifie l'entre-deux : le script lit `tools/oracle/inputs/long-prompt.txt` (844 tokens pour le tokenizer Qwen), la longueur de séquence de la référence relevée pour que rien n'en soit coupé, et le contrôle lit le même prompt comme l'app l'admet.

```sh
oracle-env/bin/python tools/oracle/z-image.py text --long
siliconed check z-image tokenizer --long
```

**L'édition.** L'édition de Qwen-Image-2.1, avec une et deux images de référence, fait partie de son `all` et de `siliconed check qwen-image-2.1` ; une étape seule, c'est `siliconed check qwen-image-2.1 dit --edit 2`. Ses références en bf16 s'écrivent avec `--edit N` (`qwen-image-2.1.py bf16 --edit 2`). Les images lues sont celles de `tools/oracle/inputs/`, que le script copie à côté des goldens.

**L'image de départ.** `img2img` part de l'image de l'oracle à la force 0,6 : l'encodeur du VAE (z₀) contre la référence, le premier pas et son σ exacts, le latent de départ au bit près, puis le rendu de l'app depuis l'image, dont le PSNR est dit sans être jugé. La mesure de Z-Image est lâche : par position, le pire écart relatif de la référence bf16 elle-même est de 0,75, sur une cellule presque nulle. Qwen-Image-2.1 édite par référence et n'a pas cette étape.

**La Compact.** Son DiT est le fichier int8 de son éditeur (l'int8 convrot de Comfy-Org et, pour Anima, de Bedovyy), que l'app lit tel quel et épingle par dépôt, révision et sha256 (`siliconed verify <modèle> --variant compact` le rehache). Le moteur multiplie ces codes int8 × int8 au GPU (W8A8) et les déquantifie dans ses fonctions sur le Neural Engine (W8A16), en f16 ([ENGINE](ENGINE.fr.md)). La Compact se juge **au DiT, contre la recette même de son éditeur sur les mêmes entiers** : l'`int8_linear` par défaut de ComfyUI (comfy_kitchen 0.2.37) calculé sur les entiers publiés par le script `w8a8`, au témoin float64 là où il existe, plus 25 %. Son rendu est dit, pas jugé : une image finie, et son PSNR contre l'image float32 affiché sans barre.

```sh
siliconed install z-image --variant compact
oracle-env/bin/python tools/oracle/z-image.py dit --size 512 --variant compact
oracle-env/bin/python tools/oracle/z-image.py witness --size 512 --variant compact
oracle-env/bin/python tools/oracle/z-image.py w8a8 --size 512 --variant compact
siliconed check z-image dit --size 512 --variant compact
siliconed check z-image render --size 512 --variant compact
```

Ces goldens demandent d'abord le golden `dit` de la Standard à 512 (ils en lisent les entrées). Pour les autres modèles, la barre s'écrit de même par `w8a8 --variant compact` ; la ligne `dit` de `check list` nomme les autres scripts, et une étape sautée dit celui qui manque.

**Les LoRA.** Un LoRA se lit dans le fichier de son auteur et se calcule à côté du produit qu'il nomme, dans la fonction qui calcule ce produit ; il n'est jamais fondu dans les poids. Trois étapes le jugent contre une référence qu'écrit l'oracle de ce dépôt. `moss-image dit-lora` prend le LoRA de la recette du modèle (ses goldens sont dans `all`) et `anima dit-lora --lora FICHIER` un LoRA kohya que vous donnez à l'oracle et au contrôle (`anima.py lora`, `witness`, `lora-bf16`, chacun avec `--size 512 --lora FICHIER` ; 448 modules reconnus et appliqués chez nous) : toutes deux au témoin float64, contre la référence bf16 qui porte le LoRA à part. `qwen-image-2.1 dit-lora --lora FICHIER` prend un LoRA aux noms de PEFT (`qwen-image-2.1.py dit-lora --lora FICHIER` ; le script nomme le fichier du golden publié, sa source et son empreinte : 224 modules, fondus dans les poids fp32 comme diffusers les charge), contre la référence bf16 sans le LoRA. Les étapes des autres familles n'ont pas de telle référence : `z-image block-lora` contrôle chaque chemin de bas rang contre le CPU, produit par produit, et `z-image render-lora --lora FICHIER` qu'un LoRA atteint l'image ; `krea2 dit-lora` juge le changement qu'un LoRA apporte à la Compact contre celui qu'il apporte à la Standard. Sans `--lora`, une étape qui en demande un est sautée.

**Un modèle importé.** `siliconed check <modèle> import` place le DiT installé dans une bibliothèque d'essai, sous un autre nom, comme un modèle que vous auriez importé : il doit être reconnu pour sa famille et rendre l'image du modèle publié, au-dessus de 50 dB. Pas d'oracle. Ce que l'étape ne prouve pas : un fine-tune réel, sous un préfixe de checkpoint ou dans une autre arithmétique que celle de la version installée.

**Le rédacteur.** `siliconed check qwen-image-2.1 writer` juge l'écriture de prompt de Qwen3-VL-8B : identifiants et pixels au bit près, logits contre la référence quand on lui impose ses jetons, et le décodage glouton avec son cache. Avec `--variant compact`, les jetons sont dits sans être jugés.

## Durées et pic de mémoire

`siliconed check` juge la justesse, et la mémoire contre le plan du moteur ; il ne juge aucune durée (l'étape `render` dit les siennes). Les durées et le pic de mémoire d'un rendu se mesurent avec l'app seule : `silicontrol measure` ([REMOTE-CONTROL](REMOTE-CONTROL.fr.md#la-prise-et-le-protocole) ; `silicontrol help measure` en liste les options) rend une série dans l'app, chronomètre chaque rendu, échantillonne la mémoire de l'app et écrit un TSV et son résumé. Vous pouvez donc refaire sur votre Mac les chiffres de [ENGINE](ENGINE.fr.md#les-chiffres) avec l'app seule, sans Python ni oracle.

**La mémoire a un budget, et il se contrôle.** Le moteur planifie chacun de ses étages (l'encodeur de texte, le DiT, le décodeur : chacun quelques fonctions Core AI et la mémoire où elles travaillent) sous un budget B = ¾ · RAM − 2 Gio, avant d'allouer quoi que ce soit, et refuse ce qui ne tient pas ([ENGINE](ENGINE.fr.md#la-mémoire-et-le-budget)). Ce qu'il prévoit, P, est l'empreinte du processus à l'ouverture de l'étage plus l'arène qu'il alloue ; ce que Core AI tient pour ses fonctions se lit pendant que l'étage tourne, et les poids gardés en mémoire au-delà de P ne le sont que tant que B les tient avec une marge de 64 Mio à côté. `siliconed check <modèle> memory [--size 1024]` rend une image et lit l'empreinte du processus pendant que chaque étage vit : chacun doit rester sous B moins cette marge, le processus sous B, et aucune page ne doit être échangée. Pas de référence : l'étape est jugée contre la parole du budget. Les lignes `memory` et `swap` de tous les autres contrôles appliquent la même règle aux étages du moteur qu'ils ouvrent.

`SILICONED_MEMORY_BUDGET_GB` donne B au processus, en Gio : le budget d'un petit Mac, essayé sur un grand (10 pour 16 Go de RAM, 4 pour 8).

```sh
SILICONED_MEMORY_BUDGET_GB=10 siliconed check z-image memory --size 1024
```

**Le décodeur par bandes.** Quand le décodeur entier ne tient pas sous B, le plan le prend par bandes de rangées. `siliconed check <modèle> vae-bands` le juge sous un petit B (`--budget` en donne un autre) ; il lit le latent du golden `vae`. Pour Anima, Krea 2 et Qwen-Image-2.1, à 1024², chaque valeur de l'image doit être celle du décodeur entier, au bit près. Les décodeurs de Z-Image et de MOSS-Image prennent leurs normes sur le plan entier : par bandes ils ne donnent pas les mêmes bits, et se jugent par la règle de l'étape `vae`.

**Le rédacteur.** `siliconed check qwen-image-2.1 writer-memory` fait de même pour une réécriture, et pour une description avec `--describe <image>` : vert au deuxième passage.

**Une graine est la graine de diffusers, sur les cinq modèles.** Le bruit de départ est celui de PyTorch : `torch.randn` sur le CPU en float32 (`torch.Generator("cpu").manual_seed(graine)`, Mersenne Twister puis Box-Muller par blocs de 16), reproduit au bit près, tiré dans la forme que tire le `prepare_latents` de chaque pipeline — le latent plan par plan, comme le moteur le range. `swift test` garde les premières valeurs, celles du milieu et les dernières de ce bruit pour Z-Image, Anima, Krea 2 et MOSS-Image, à 512² et sur un rectangle, relevées une fois avec diffusers ; l'étage de trajectoire de chacun des cinq modèles le compare aussi au `latent_init` de l'oracle, à la graine que nomme son manifeste. La même graine et le même prompt partent donc du bruit dont part diffusers ; l'image qui suit se juge par les règles ci-dessus, étage par étage, et ses bits ne sont promis ni d'un Mac à l'autre ni d'une version de macOS à l'autre. Une variation tourne ce bruit vers celui d'une seconde graine, tiré de la même façon. Le bruit frais des solveurs (Euler a) n'est pas la recette de diffusers et ne le prétend pas.

## Toutes les étapes

La sortie de `siliconed check list --markdown`, telle que la commande l'écrit, en anglais. Les scripts s'y lisent depuis `App/`. `{size}` vaut 512, 1024 ou un rectangle comme 768x512 ; les étapes sans taille se contrôlent à celle de la référence.

| Stage | Proves | Rule | Oracle | Weights |
|---|---|---|---|---|
| `z-image tokenizer` | the chat template and the tokenizer give transformers' 512 identifiers and mask, padding included, and the app's admission the same real tokens (with --long, past 512: 1024) | bit for bit | `tools/oracle/z-image.py text [--long]` | tokenizer |
